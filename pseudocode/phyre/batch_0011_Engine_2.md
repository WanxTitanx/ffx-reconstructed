## Summary

This batch covers 24 more `Engine_*` functions in FFX.exe — continuing the MSVC 2012 v110 STL infrastructure + PhyreEngine's memory accounting + endian conversion utilities. Most functions in this batch are small (113-210 bytes) STL wrappers or Phyre memory tracking helpers.

**Key discovery:** `Engine_ByteSwap64_to_LE` and `Engine_ByteSwap64_to_BE` are MSVC compiler-generated byte-swap intrinsics (single basic block, no branches), called by Phyre's `Phyre_Endian_SwapDouble`, `SwapPUInt128`, `SwapPUInt64`, `SwapPInt64` — confirming FFX.exe was originally written for big-endian (PS2/PS3) and ported to x86 little-endian via byte-swap wrappers.

## Key Findings

1. **Big-endian origin confirmed** — `Engine_ByteSwap64_to_LE/BE` are MSVC compiler-generated bswap intrinsics (single basic block). FFX.exe was ported from big-endian (PS2/PS3 PhyreEngine) to x86 little-endian via these wrappers. Phyre_Endian_SwapDouble/SwapPUInt128/SwapPUInt64/SwapPInt64 use them.

2. **Memory accounting system** — `Engine_MemAlloc_FindRecord` + `ArrayInsert` + `AggregateStats` together form Phyre's memory tracking. Each allocation gets a 148-byte record (category + 2 strings + count + size + 128-byte metadata blob). Global linked list at `unk_C96290`.

3. **MSVC STL inline functions shipped as separate funcs** — `std::stringbuf::stringbuf(const std::string&)` is its own function `Engine_stringbuf_ctor_from_string` instead of inlined. Compiler chose to not inline due to size.

4. **Engine_String_find heavily used** — 25 callers across config parsing, shader resource loading, VFX resource loading, PS3 data loading, and battle UI path detection. Critical for FFX's resource lookup pipeline.

5. **Engine_AlignedRealloc is NOT stdlib-style realloc** — does not copy old data. Just allocates new aligned buffer. Caller is responsible for memcpy. This is intentional for performance (avoids memmove on large buffers).

6. **PString has inline optimization** — `Engine_PString_Expand` uses count=0 (no buffer) and count=1 (inline 4 bytes) cases. Larger buffers use heap via `Engine_PString_Expand_Resize`.

7. **Locale category lookup is hard-coded** — `Engine_std_GetLocaleCategory` compares against hard-coded tables at `unk_B7CBA8` (FFX custom locale data). Used only by `FFX_MenuAudio_ApplySettingsData`.

8. **Endian swap = compiler intrinsic** — Both `Engine_ByteSwap64_*` functions are MSVC `_byteswap_uint64` intrinsic expansions. Zero branches, single basic block, ~10 instructions each.
