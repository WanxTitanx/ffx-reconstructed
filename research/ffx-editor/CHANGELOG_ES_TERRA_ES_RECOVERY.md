# Registro de cambios

Este archivo registra la evolución oficial de `FFX Project Editor` y del ecosistema de talleres `Pt`.

Cubre tres niveles de historial:

- releases y baselines de la `main`;
- milestones semánticos reconstruidos de la `main` durante el período pre-Git oficial;
- mini-versiones editoriales y knowledge snapshots de los talleres `Pt2` a `Pt45`.

Reglas de este registro de cambios:

- **regla vigente (desde 2026-06-04, ver `docs/governance/VERSIONING.md` sec. 4):** toda adición **shippable** (writer, módulo, prueba, capacidad, doc-de-registro) entra con bump en los 4 campos de `FFXProjectEditor.csproj` + una entrada aquí **y** en `changelogUS.md` + una línea en `VERSIONING.md`;
- clasifica cada entrada: **MINOR** / **PATCH** / **REVISION**; firma con lane (`Jarvis-ARENA`, `Jarvis-MAGIC`, etc.) cuando haya multi-chat;
- mantén la cadena `[anterior: vX.Y.Z.W]` lineal — sin saltarse números;
- **sin bump** solo para lo trivial (typo, whitespace, rename interno, refactor byte-idéntico sin fix);
- registra también hitos, absorciones, freezes, bloqueos y handoffs;
- no finjas un historial antiguo de Git que nunca existió;
- cuando una versión semántica antigua fue reconstruida editorialmente, márcala como `historical reconstruction`;
- cuando un taller cambia mucho el proyecto pero no entra en la `main`, aparece aquí como un cambio del ecosistema, no como una feature ya portada.
